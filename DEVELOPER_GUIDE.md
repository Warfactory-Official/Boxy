# Boxy Developer Guide

## Current Architecture

Boxy 2.x is one ordinary **NeoForge 1.21.1 / Java 21** addon. Voxy is a separate, unmodified native mod. This guide replaces the Forge 1.20.1 loader guide; Git history retains the old implementation and its debugging notes.

There is no service-layer Boxy module, Fabric facade, bytecode remapper, synthetic Voxy entrypoint, Mixin Transmogrifier, shader-asset copying, SRG mapping corpus, or nested game-layer bundle.

`BoxyVss` registers payload handlers and server services. `BoxyClient` is a separate client-only entrypoint. `src/main/resources/META-INF/neoforge.mods.toml` and `boxy.mixins.json` describe the actual shipped mod. Dedicated servers need no renderer dependencies.

Dependency baseline: NeoForge 21.1.248, Voxy 0.2.15-beta from the selected multiversion source, Sodium 0.8.12-beta.2, optional Iris 1.8.14-beta.1. Voxy uses internal APIs, not a stable addon API; update the pin and test together.

Plain helpers/interfaces must **not** live inside a configured mixin package. Doing so causes `IllegalClassLoadError` when game code tries to load them.

## Networking

`VssPayload` implements `CustomPacketPayload`. Each message has a typed `boxy:*` ID; registration uses `RegisterPayloadHandlersEvent`, `StreamCodec`, and an optional `PayloadRegistrar` explicitly set to `HandlerThread.MAIN`.

Protocol is **20**, with registrar version `boxy-1.21.1-20`. It is Boxy-to-Boxy and requires matching client/server versions. Block/biome palette values use the connected Minecraft 1.21.1 registries. Timestamp `-2` explicitly requests a dirty refresh; `-1` remains ordinary uncached discovery.

The optional `MixinHbmChunkCarver` intercepts HBM's shared crater/fallout `repairAndResend` relight future. It holds a temporary FULL ticket until the callback (with a 200-tick expiry safety net), signals dirty tracking after lighting completes, and posts `BulkTerrainUpdateEvent`. In singleplayer, `BoxyServerIngest` copies every section and its lighting directly into Voxy, including newly empty sections, independently of VSS reception and vanilla player tracking. This path respects `liveDirtyUpdates`, preserves uniform skylight, and rejects stale server-session callbacks. HBM is neither bundled nor required. Test the actual optional dependency with `runSmokeClient -Psmoke -Phbm_smoke -Phbm_jar=<jar> -Pgolemcore_jar=<jar>`; it uses the separate `run/hbm-smoke` directory and disables VSS reception in memory to verify the direct path.

Dirty refreshes falling back to disk confirm an existing FULL column, then reacquire a temporary FULL/non-ticking ticket and serialize a live snapshot before releasing it. This handles editors that release their own tickets before the dirty broadcast. Reloads are limited to 32 globally and 8 per player, retry on saturation or missing saved data, time out after 160 ticks, and use the existing snapshot budget. Cancel, dimension departure, disablement, and shutdown release tickets. Ordinary discovery continues to use disk directly; missing dirty columns are not generated by this path.

Never send optional packets without `hasChannel`. The client handshakes even if terrain streaming is disabled, allowing entity configuration sync. Capability zero also covers an installed-but-disabled Voxy instance. Compatible handshakes establish server entity sessions independently of terrain generation/streaming settings.

World access, ticket operations, orchestration, and payload dispatch handlers are confined to their logical main thread. Worker-owned pending maps and limiters are mutated only by the processing thread. Worker tasks receive immutable tick snapshots or copied section data. Preserve per-player/global concurrency and bandwidth limits and the response batch cap.

## Terrain Pipeline

Server tick processing drains completed work, probes loaded chunks, snapshots live data, dispatches workers, polls generation, and flushes bounded player queues. Disk reads use public `ChunkStorage.read(ChunkPos)`, inherited by `ChunkMap`; no reflection or access transformer is needed.

`ColumnSnapshotter` copies live block states and lighting on the server thread. It preserves the section's actual `nonEmptyBlockCount` via an accessor rather than recomputing it. A worker then emits the section byte layout. Do not move live palette copying to a worker or publish mutable tick maps.

Live dirty detection covers ordinary `ServerLevel.sendBlockUpdated` notifications and `ChunkAccess.setUnsaved(true)` on server `LevelChunk` instances. The latter catches bulk section edits such as HBM crater carving and fallout that bypass ordinary block notifications. Repeated true calls are intentional: a chunk can be edited again after a dirty broadcast but before autosave. Cache invalidations are coalesced once per dimension/column per drain window. The bulk hook also sees non-terrain dirty notifications (for example block-entity persistence); this favors correctness but may increase broadcast traffic in machine-heavy worlds. ProtoChunk generation and client chunks are excluded.

Generation tickets use radius **0**, giving chunk level 33/FULL without requesting block/entity ticking. Frozen entity-load tickets also use radius 0, with **player UUIDs as owners** so overlapping players cannot remove each other's tickets. Frozen loading remains default-off. `forceLoadRadiusChunks` is a square radius around each discovered entity, not the player. A compatible player within `entityTrackingDistanceChunks` activates that entity's window; overlapping windows are deduplicated per player. Only chunk coordinates are cached, so activation conservatively measures distance to the chunk boundary and native tracking applies the exact entity distance after loading.

Discovered non-player entities are indexed by UUID/type/chunk in each dimension's `data/boxy-discovered-entities-v1.dat` SavedData, including while force-loading is disabled. Discovery requires the entity to have been loaded at least once; this is not an offline scan of old world files. Movement updates the index, chunk unload preserves it, and destruction or dimension departure removes the old entry. Stale entries are checked in bounded batches only after terrain and asynchronous entity storage are loaded. The persistent index uses spatial buckets for player queries. Player logout, dimension changes, tracking disablement and server shutdown release tickets, but retain discoveries. Loading can generate neighboring terrain; cost scales with the union of active entity windows. Entities outside normal ticking chunks remain frozen.

The edit hook on `ServerLevel.sendBlockUpdated` marks loaded columns dirty immediately. The `ChunkMap.save` hook remains a backstop. Dirty updates cannot observe unloaded-world changes without a server-side load source.

The client decoder has world/session-owned queues bounded by both column count and a 64 MiB encoded-byte budget. Deserialization can run on a worker; ingestion and Voxy engine acquisition run on the client thread, serialized against client session shutdown. Late results from a previous level/session are discarded. Requests are matched by ID, dimension, and position, and are acknowledged/cached only after successful ingestion. Malformed sections and failed ingestion leave terrain retryable.

On a cached-column update, omitted sections are ingested as air to clear structures that disappeared. An entirely empty payload is also an update, not something to silently discard. The retained protocol deliberately omits all-air sections without block light; changes to that optimization require checking all three serializers and the client together.

## Cache Boundaries

- Client validation cache: `config/boxy/cache-1.21.1-v20`, format 4 only.
- Server timestamp cache: world `data/boxy-timestamps-1.21.1-v20.bin`.
- Config filenames remain `vss-client-config.json` and `vss-server-config.json`.
- Old Forge caches are neither read nor deleted. Voxy's own database is separate; Boxy does not migrate it.

Request IDs do not reset on dimension changes. Dimension resets clear pending work and return permits, including when a transition snapshot is replaced before the worker consumes it. Late disk/live results stay in their captured original result queue; completions match request IDs instead of just coordinates. Dedup groups include dimension and primary request ownership. Generation tickets/results carry their source dimension and are discarded across transitions.

Timeout callbacks reopen the affected spiral ring even while the player is stationary. Incremental scanning remains opt-in; preserve its dirty-ring and timeout invariants. Diagnostics/metrics scaffolding is intentionally retained for future commands/HUDs.

## Distant Entities

Minecraft 1.21.1 requires **both** server gates to be lifted: effective tracking distance and `ChunkMap.isChunkTracked`. The latter still preserves the pending chunk-send check; entity `broadcastToPlayer` restrictions remain untouched. Only configured types and successfully handshaken Boxy clients receive the extension.

Client gates are `Entity.shouldRenderAtSqrDistance`, `LevelRenderer.isSectionCompiled`, and the dispatcher cull check. The section bypass explicitly captures the current entity and checks its type. Foreign culler overrides retain frustum testing and degenerate-box/leash handling.

`DistantEntityTicker` handles configured entities absent from `ClientLevel.tickingEntities`. It skips local players and passengers, preserving normal ticks. Non-living entities are pinned to packet-authoritative Y/rotation after ticking, since LOD terrain does not provide collision. The packet hook uses 1.21.1's six-argument `Entity.lerpTo(DDDFFI)V`, including both movement call sites and teleport.

Server whitelists/distance apply in memory only. Local `extendEntityRenderDistance=false` always opts out. Namespace wildcards resolve lazily after mod registration. Logout clears sync and position state.

## Rendering Contracts

`DistantEntityDepthFix` uses a private `ByteBufferBuilder`/`BufferSource`. Minecraft 1.21.1 keeps camera rotation in **RenderSystem's model-view matrix**, separate from the entity PoseStack; combine them when computing eye-space depth. The projection's x/y rows remain unchanged. Immediate buffers can flush during RenderType changes, so apply the band around the entire build plus final flush.

Basic mode re-bands depth into the entity's true window-depth interval. Precise mode uses stencil bit 7 for mask/clear/fine/restore passes. It falls back under shaderpacks, an already-active stencil test, unsupported/reversed projections, nonstandard depth ranges, glowing-outline buffers, oversized bounds, and far-plane degeneracy. Stencil attachments are enabled between frames, not mid-render, and not while shaderpacks are active.

Custom depth passes save/restore touched depth, color-mask and front/back stencil state. Failed entity builds discard/recreate the private native buffer instead of leaking partial geometry into later entities. The shader LOD-depth join distinguishes Voxy's source depth convention from the destination clip convention and uses a per-renderLevel frame boundary, not Voxy's debug traversal counter.

`MixinVoxyLodDepthCapture` captures the actual GL clip-depth mode at the end of the LOD producer pass, along with its framebuffer and viewport. Never substitute `RenderProperties.isZero2One()` for this measurement: that flag describes projection construction, not OpenGL's storage mapping. The join runs for both normal and Iris pipelines, before entity precision logic even when the precision setting is Off. A frame with no completed LOD pass cannot reuse stale depth. The normal-pipeline fog-suppressed colour case remains excluded.

Iris/shaderpack support remains rendering-sensitive. Successful launch with Iris and shaders disabled does **not** validate a shaderpack, shadow pass, scaled framebuffer, or exact terrain occlusion. See migration verification notes before release.

## Mixins and Dependencies

Use official Mojmap names for Minecraft targets. No hand-SRG names or runtime selector remapping. Required core entity hooks fail loudly if the pinned version changes. Optional dirty/third-party fixes use `require=0` only where graceful degradation is intentional.

Voxy-specific mixins remain in Boxy's own config. Do not modify Voxy's mixin JSON or jar. Upstream already supplies `/voxy`, native config, and its NeoForge Chunky integration.

For development, full Sodium/Voxy/Iris jars are installed into `run/client/mods`. Sodium's distribution has an early graphics bootstrap/service locator: adding that outer jar as a regular ModDev runtime classpath mod can drop its nested implementation. The solution is normal native mod discovery, **not** unpacking/rewriting Sodium or introducing another loader shim.

## Verification

See README for commands. `test` runs deterministic request-tracking regressions. `verifyProductionJar` rejects embedded Voxy, old loader packages, service registrations, nested legacy bundles, and smoke-test classes. `-Psmoke` defines isolated `runSmokeClient`/`runSmokeServer` tasks with a separate, non-production test mod. It never alters normal `runClient`/`runServer` loaded mods, JVM arguments, or directories.

`verifyClientLaunch` regenerates `build/moddev/clientRunVmArgs.txt` and rejects smoke properties or geometry-memory overrides there. Smoke runs generate their own `smokeClientRunVmArgs.txt`. This separation matters for IDE launches that consume the generated files without reevaluating Gradle: using the same run name previously leaked the 256 MiB test cap into normal play. The selected Voxy's `NodeCleaner` starts eviction below 256,000,000 free bytes, so that cap left only about 12 MiB for geometry and caused continuous eviction/rebuild flicker. Smoke tests now use 1 GiB by default; normal play retains Voxy's native allocation policy.

The dedicated smoke checks startup/shutdown, ChunkMap/section accessors, section wire round trips, snapshot serialization, uniform lighting and entity-tracker mixin application without client dependencies. The client smoke checks Voxy renderer creation, native Sodium option registration, integrated streaming, and rendering a pig beyond four-chunk view distance. Its memory override is test-only.

`-Psmoke -Pocclusion_smoke` is a separate GPU regression: calibrate a visible ghast, insert a LOD-only wall in front, then require zero passing samples from its depth-banded draws. `-Pocclusion_distance=832` exercises the long-distance normal pipeline. The fixture submits detached wall sections directly to Voxy so request/cache timing cannot be mistaken for a rendering defect. `-Pocclusion_control` disables the join in the test mod only and is expected to fail, proving the test detects the missing repair.

`-Pocclusion_depth_mode=OFF` measures the original entity buffer instead, flushing just the test entity inside its GPU query. It also requires a depth join to execute, so moving the repair back behind the precision-mode guard cannot silently pass this variant.

Before release, additionally test two real clients, moving players/vehicles, passengers, rapid reconnect/dimension changes, editing/emptying streamed columns, generation cancellation, overlapping frozen tickets, vanilla-peer connections, Chunky, and the supported shaderpack matrix. Do not describe build success or draw-call counters as visual correctness certification.
